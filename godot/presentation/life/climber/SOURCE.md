# Climber body asset

The GLB byte stream and both rig metadata files originate byte-for-byte from ScraperX
revision `82cb58992f9ecd300830e6289d25367e6bc0e6b7`, under
`godot/presentation/life/climber/`. The GLB is packaged with the `.bytes` suffix described below; the original body was retained, not rebuilt.
GLB SHA-256: `918c244ec10ae8cfaeea57cd6f40deacec547f57e73145059b2b199e91922c8e`.

## Provenance and license

The source body's mesh, morph targets, skeleton and weights come from
[MakeHuman Community](https://github.com/makehumancommunity/makehuman), pinned to
`a8bc2d54ff0ac92e78ff71431b1023eda42bf482`. The project's original builder uses
its own data parsers in `tools/body/human.py`; it does not copy MakeHuman program
code. Clothes and boots are generated by `tools/body/build_climber_body.py` from
the body, offset shells and lofts. The head and arms form a simplified shadow
mesh. No textures are embedded or referenced.

Primary upstream evidence checked on 2026-10-21:

- [Base mesh header](https://github.com/makehumancommunity/makehuman/blob/a8bc2d54ff0ac92e78ff71431b1023eda42bf482/makehuman/data/3dobjs/base.obj) explicitly releases the mesh as CC0; it identifies Data Collection AB, Joel Palmius and Jonas Hauquier as the 2020 copyright holders.
- [Default skeleton](https://github.com/makehumancommunity/makehuman/blob/a8bc2d54ff0ac92e78ff71431b1023eda42bf482/makehuman/data/rigs/default.mhskel) and [default weights](https://github.com/makehumancommunity/makehuman/blob/a8bc2d54ff0ac92e78ff71431b1023eda42bf482/makehuman/data/rigs/default_weights.mhw) declare `license: CC0`.
- [Asset license](https://github.com/makehumancommunity/makehuman/blob/a8bc2d54ff0ac92e78ff71431b1023eda42bf482/LICENSE.ASSETS.md) is CC0 1.0 Universal, copied here as `LICENSE.MakeHuman.txt`.

`tools/body/sources.json` preserves the original pinned source URLs and SHA-256
hashes, including morph data. CC0 describes those upstream data assets; this
notice does not assign a new license to ScraperX's own builder code or generated
clothing additions. Those additions retain their existing project provenance.
The manifest is shared with the original Matron builder and includes inputs
unused by this climber. Its fetcher is optional build tooling, never a runtime
step. No MakeHuman asset pack or program dependency is needed to import the GLB.

## Model and renderer contract

Units are meters, soles at Y=0, facing +Z. The root node is `ClimberBody`.
The eight mesh node names are `trousers`, `jacket`, `jacket_inner`, `hivis`,
`zip`, `boots`, `soles`, and `shadow`. Set `shadow` to shadows-only in the
renderer: the GLB alone does not encode that Godot visibility policy.

There is one skin with 56 bones. Leg chains from `body` are
`hp_l → hp_l_x → kn_l → kn_l_x → an_l`, with the right side using `_r`.
The `_x` entries are intermediate leg bones; preserve the imported hierarchy.
Torso bones are `body`, `spine_lo`, `spine_mid`, `chest`, `neck_lo`, `neck_hi`,
`head`, and `jaw`. Full names, parent links and local rest transforms are in
`climber_body_rig.json` and match the GLB. The renderer must use imported bone
rest transforms when posing these bones.

`climber_body_rig.gd` contains the generated rest-pose constants:

- `EYE = (0, 1.52, 0.11868)`; `THIGH = 0.39092`, `SHIN = 0.39786`.
- `HEEL_L = (0.00521, -0.08064, -0.08323)`; `TOE_L = (0.03430, -0.12375, 0.18060)`.
- `HEEL_R = (-0.00521, -0.08064, -0.08323)`; `TOE_R = (-0.03430, -0.12375, 0.18060)`.

Heels and toes are positions in each ankle/foot bone's local rest frame,
not world-space offsets. JSON retains full precision; GDScript rounds to five
decimal places. The renderer consumes native contacts; this asset supplies no
physics, gait controller or alternative contact authority.

## Measured source cost and validation

`python3 -I tools/body/inspect_climber_body.py` uses only Python's standard
library. It checks GLB headers, bone names/parents/local rest transforms against
JSON, matching skin attribute counts, four skin weights per vertex, and mesh
triangle counts against metadata. Observed exit code: 0 on the adopted files.

| Mesh | Vertices | Triangles | Surfaces |
| --- | ---: | ---: | ---: |
| trousers | 1,638 | 2,960 | 1 |
| jacket | 1,687 | 3,064 | 1 |
| jacket_inner | 98 | 96 | 1 |
| hivis | 147 | 192 | 1 |
| zip | 48 | 46 | 1 |
| boots | 1,884 | 3,168 | 1 |
| soles | 112 | 216 | 1 |
| shadow | 2,440 | 5,382 | 1 |
| Total | 8,054 | 15,124 | 8 |

The GLB is 789,148 bytes with eight materials and no textures. Visible clothing
and boots account for 5,614 vertices and 9,742 triangles across seven surfaces;
the shadow part adds one surface. These are source counts, not measured Godot
draw calls or frame times. Each rendered pass may submit its participating
surfaces; shadow cascades and lights add passes. Skin weights use four slots per
vertex, with one shared 56-bone skin.

## Optional regeneration

The original `build_climber_body.py`, `human.py`, `fetch_makehuman.py` and
`sources.json` were retained from the same ScraperX source revision. The
builder's output filename uses the packaged `.glb.bytes` suffix.
Regeneration requires NumPy and the pinned source inputs; neither is needed for
runtime. No packages were installed and regeneration was not run during adoption.
From the repository root, with those prerequisites available:

```sh
python3 -I tools/body/fetch_makehuman.py build/makehuman
python3 -I tools/body/build_climber_body.py build/makehuman godot/presentation/life/climber
```

The shared fetcher downloads all manifest entries, including other character
inputs. The copied GLB byte stream and rig files are the authoritative adopted artifact;
a later regeneration must be reviewed rather than assumed byte-identical.
Godot import sidecars/caches were deliberately not copied so this project assigns
fresh import identities. Import, rendering and device performance are separate
integration checks, not established by the source inspector.

Runtime packaging adaptation: the GLB byte stream is unchanged, stored with `.bytes` so Godot exports it as an explicit raw file. `first_person_body_rig.gd` reads it using GLTFDocument.append_from_buffer; it does not require an editor-generated scene cache. The builder and inspector use the packaged filename.
