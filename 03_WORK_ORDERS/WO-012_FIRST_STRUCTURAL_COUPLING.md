# Work Order 012 — First Structural Coupling (KX-NEEDLE / KX-POCKETS)

**Note on numbering:** this is Ascent Atlas v1.0's kernel content for "Work Order 006 — first structural coupling" (`WO-006_FIRST_STRUCTURAL_COUPLING.md` in the v1.1 build package). It is renumbered WO-012 for the same reason WO-005 became WO-011: repo WO-006 already names other, earlier content (the Kellerworks coupled machine) committed before the atlas existed. See WO-011's own numbering note for the full precedent.

## Objective

A seated structural member changes support and traversal.

Atlas kernel (§9): `KX-NEEDLE` seated in `KX-POCKETS` becomes walkable/load-bearing. Unseated, the span is a gap or an untrusted rest.

## Existing proven truth

WO-011 proved a pendant-controlled crane (`KX-JIB`) moving one real load (`KX-CRATE`) under finite limits. Nothing in the repo before this WO gave a structural member itself a discrete seated/unseated identity that the support and traversal system reads — every prior support (deck, ledges, crate, lift platform) is permanently and unconditionally a support the instant it exists.

- Governing Law 26 — no physics theater / no second authority: seated vs. unseated is decided by real constraint topology, not a flag.

## Owner

Native structural state. Jolt owns the rigid body/contact of the needle as a mass. Structure (native `update_needle`/`seat_needle`/`unseat_needle`) owns pocket connection, whether the span is a valid support, and persistent seating. Neither side independently invents "broken" vs "seated" — support and traversal read the same Jolt contact the seat pins actually produce.

## Allowed seam

One mechanism definition: a second, minimal jib-pattern hoist (mast + one finite-force vertical motor, no slew) plus two static piers. Godot exposes Raise/Lower only while the player is within the needle pendant station radius, mirroring WO-011's contract exactly.

## Design decisions (stated, not left implicit)

- **A second, minimal hoist carries the beam, rather than reusing WO-011's jib.** The atlas's kernel chain reads "player seats KX-NEEDLE with the jib," and `KX-JIB` is a single named module — but WO-011's jib hook is already permanently pinned to `KX-CRATE`, and building a proximity attach/detach system to let one hook carry two different loads was explicitly out of scope for WO-011 and is not asked for by WO-006 either ("Implementation scope: KX-NEEDLE + KX-POCKETS... seat/unseat topology..." — no attach/detach system named). A second hoist, built with the exact same architecture (static mast, `EMotorState::Velocity` slider, station-gated pendant) proven in WO-011, satisfies "a real, jib-pattern mechanism does the industrial travel" without inventing a harder, unrequested capability.
- **No slew.** The hoist mast is sited directly above the gap centreline, so the beam only ever needs to travel straight down into the seat — a "reduced-order connection," which WO-006 explicitly sanctions ("Exact beam formulation remains TDD-gated... do not invent FEM to finish this WO"). This also removes any horizontal-alignment failure mode by construction, rather than by tuned tolerance.
- **The seated beam's top sits flush with the pier tops — a real recessed pocket, not a shelf.** Found necessary by direct observation, not assumed: an earlier version seated the beam proud on top of the piers (bottom flush with pier top), leaving a 0.36 m step at the near edge. This game's locomotion is a raw dynamic capsule with no step-up assist at all (confirmed the same way — the player was flatly blocked, not slowed), so any step at the seat is an impassable wall, not a climbable lip. Each pier is now two static boxes: a full-height main block, and a shorter notch block under the 0.9 m overlap strip, recessed by the beam's own thickness so the seated beam's exposed top continues the pier top exactly level. `KX-POCKETS` reads correctly as a recess, not a rest.
- **The notch's boundary against the main block is pulled back 0.2 m from the beam's own resting edge**, rather than exactly coincident with it. Also found by direct observation: siting that boundary exactly at the beam's edge left the descending beam stopping ~4 cm short of its seat every time, against `JPH::BoxShape`'s default rounded convex radius on the main block's corner (the two boxes only ever share a boundary plane in exact geometry, but Jolt's default speculative-contact/convex-radius margins do not respect an exactly-coincident boundary). The margin removes the ambiguity outright rather than tuning around it.
- **The hoist stays permanently connected to the beam, seated or not** — the same sidestep WO-011 used for the hook-to-crate pin, avoiding a second attach/detach system. This slightly over-constrains the beam once the two pocket pins also exist (a slider plus two point constraints on one rigid body), which is harmless here because all three are geometrically consistent by construction (the slider's own rest point coincides exactly with the pocket points).
- **A sustained raise command while seated is the legal unseat path** (WO-006 proof path item 2: "if a legal unseat path exists"). It removes both pocket pins first, then the same real motor lifts the now-free beam clear — never a flag flip. The seat predicate itself is gated on "not actively commanding a raise" (`hoist <= 0`): found necessary by direct observation — right after the pins are removed the beam is still sitting exactly at the seat pose with near-zero velocity for at least one tick (a real motor needs real time to accelerate it away), so an ungated predicate re-seated it the same tick, before a held raise command ever got a chance to move it. The proof-path test for unseating failed against this exact race before the gate was added.
- **The seat predicate checks height and speed, not full 3D position.** The beam has no horizontal or slew freedom at all once hung from the hoist, so its ends can only ever be at the pocket X/Z coordinates — alignment is guaranteed by construction, and the only open question is genuinely "has it come to rest at the bottom," which position + speed answers completely without inventing a beam-formulation model WO-006 explicitly says not to invent.

## Forbidden shortcuts (checked against)

- Swapping a "broken" mesh for a "fixed" mesh with unchanged collision — there is one beam body throughout; only its constraint topology (pinned or not) changes.
- Mission flag `needle_ok` enabling an invisible walkbox — support comes from the same Jolt contact listener every other support in the game uses; nothing native short-circuits it.
- Deleting the gap without a seated body — the gap is real open space between two piers; nothing fills it except the actual beam body, actually lowered.
- Auto-snap seat from Action across the room — seating only happens through a continuous, station-gated hoist command that must actually carry the beam the full ~2.4 m of real travel and settle there.
- Resetting seat on play-mode restart without going through checkpoint rules — `commit_machine_checkpoint`/`restore_from_checkpoint` capture and restore both the beam's continuous transform and the discrete `needle_seated` flag; `restore_needle_topology` reconciles pins to match on restore (see Unverified boundary below for what is and is not falsified about this path).

## Proof path

1. Host tests prove the unseated gap cannot be crossed: walking straight at it from the pendant, with the hoist never touched, drops the player rather than delivering them to pier-top height on the far side.
2. Host tests prove a sustained lower command from the pendant seats the needle — the structural predicate flips, not just a reported position — and that the seated beam is genuinely at rest, not still settling under a motor still driving it.
3. Host tests prove the seated needle is a real, walkable support specifically while the player is over the gap (not merely "reached the far side" some other way), and that the player can walk it all the way to the far pier.
4. Host tests prove the legal unseat path: a sustained raise command while seated removes the support and the beam actually rises through the same real motor.
5. Host tests prove the ordinary grounded-tick checkpoint commit captures a seated needle (the capture side of the same mechanism `restore_from_checkpoint` reads back from).
6. The Godot runtime reproduces every WO-004..011 proof line unchanged, and the pocket/pier/beam kernel geometry renders correctly from a manual vista capture.
