# CP-004 — Traversal / Impact / Identity Checkpoint

## Objective

Advance the proven exterior checkpoint through three contiguous seams without changing authority ownership:

`Fold-open exterior machine identity → native bounded athletic traversal → hopper mass physically propagates into a second native mechanism`

This checkpoint incorporates the user-supplied 2026-09-17 visual identity reference through `01_PRODUCT_AUTHORITY/support/06_VISUAL_IDENTITY_REFERENCE.md`.

## Preserved authorities

- `scraperx_sim` remains the sole owner of player pose/velocity/support/traversal state and consequential machine state.
- Jolt remains the sole consequential rigid/contact substrate.
- Godot owns input interpretation, camera, HUD, meshes, light, atmosphere, and render mirrors only.
- WO-002 moving-support velocity and inherited-momentum laws remain regression-gated.
- CP-003 exterior spawn, proximity-gated hopper command, finite gate travel, and physical hopper load remain regression-gated.

## Slice A — machine-tower identity

The lower exterior must read as monumental industrial machinery integrated into architecture rather than a thin scaffold or neon test arena.

Required presentation signals:

- heavy concrete/steel mass with open machine bays;
- weathered timber infill where appropriate;
- giant wheel/drum/crane/lift masses integrated into the facade;
- actual traversal geometry braided through that machinery;
- sparse sourced amber practicals against cool overcast daylight;
- atmospheric truncation of the upper tower;
- no decorative animation masquerading as physics authority.

Static identity machinery may remain visibly idle. Any consequential moving machine shown in this checkpoint must mirror native state.

## Slice B — bounded athletic traversal

Add three native controller primitives against actual Jolt geometry:

1. **Vault** — low blocker, bounded approach window, multi-tick ballistic/controller trajectory.
2. **Mantle** — higher ledge, bounded reach window, vertical-clearance phase followed by forward transfer onto real support.
3. **Hang** — airborne reach window at a real ledge; native corrective velocity controller arrests the fall without teleporting. Jump from hang transitions into a native mantle; explicit drop releases the controller back to gravity.

Rules:

- no Godot route flags;
- no direct position teleport;
- candidate state comes from native player/body geometry and bounded reach/clearance rules;
- ordinary locomotion and WO-002 support laws remain intact outside the assist;
- completion is judged from player body state/contact, not animation.

This is a bounded first implementation of WO-003 primitives. It is not yet a claim that all production traversal geometry or moving-ledge cases are generalized.

## Slice C — second physical machine consequence

Extend the hopper chain:

`player command → finite gate travel → dynamic hopper load → gravity/contact through chute → collision with rotation-only dynamic rocker → rocker angular state`

The rocker is a Jolt dynamic rigid body with translation locked and Rotation-X free. The downstream consequence is proven only from actual rocker quaternion/angular velocity after physical contact.

No timer, animation event, load-moved flag, or Godot transform may manufacture the rocker result.

This does **not** complete WO-005. The full freight work order still requires finite power/force/travel/braking machinery with a real movable load.
