# Macro mechanism authoring contract

**Scope:** new ScraperX ascent slices on `ChatGPT`. The Atlas owns geometry; `00_START_HERE.md` owns current status. The old AS-001–015 queue is retired, not a prerequisite list.

## Work backward, verify forward

Start with the player's supported destination. Resolve transfer geometry, load transmission, source energy and reachable control in that order. Then exercise the whole physical chain forward through normal input. Backward derivation is a design method, not evidence that a mechanism works.

| Contract | Must be stated |
|---|---|
| Receiver | Native support identity, walking surface, clear standing area, stability, onward action and fall recovery |
| Transfer | Contact/capture volume, posture/clearance, relative velocities and allowable placement variation |
| Transmission | Actual bodies, joints, contact/rope paths, arm lengths and their changing mechanical advantage |
| Source | Mass/COM/inertia, usable height or spring work, finite drive, friction/impact/braking losses and remaining energy |
| Player access | Supported approach, visible control, bounded effort, available hands and early/late input consequences |
| Persistence/retry | Spent inventory, lost loads, return path, rearm energy and a coherent checkpoint restore |

Inputs and outputs match at the same instant in position, orientation, velocity, load, available energy, constraint state and player access. Same altitude or same label does not close a handoff. Reject hidden stubs, remote attachment, route completion flags and pose snapping.

## Readability and pace

Use large geometric causes: something rolls, tips, swings, strikes, lands or becomes supported. See the major handoff from the approach or operating position. Record an actual first-person pass and a miss; UI telemetry is supplementary. Prefer wide capture regions to intricate projectile catches. The normal path must be worth doing even when legal parkour offers an alternative. Do not defend a weak mechanism with invisible barriers.

## Movement and units

SI, Y-up. Distinguish body COM from walking surface and capsule centre. The current standing capsule is 1.8 m tall, radius 0.35 m; crouched height 1.2 m; step-up 0.35 m. Inspect source/runtime for each actual reach, clearance and moving-support transfer. Preserve `v_linear + omega × r` and inherited detach momentum. Do not retune global movement to hide a local geometry flaw.

## Evidence and readiness

Label facts SOURCE, OBSERVED RUNTIME, DESIGN TARGET, HISTORICAL OBSERVATION or UNKNOWN. Keep lifecycle separate from evidence and READY/BLOCKED. A critical unresolved release load, receiver, stopping law or recovery path blocks a ready implementation contract; guessing a number does not resolve it. Use explicit local prototypes to answer those unknowns rather than importing an entire old campaign.

## 8. Mechanical close for a new ticket

Each bounded ticket names objective, existing truth, authority, native state owner, allowed seam, forbidden shortcuts, actual proof path and completion condition. Include the contracts above, one legible normal sequence, physically meaningful negative cases and the player's terminal support. A ticket may span files but should implement one useful causal slice.

Proofs must distinguish normal gameplay from an explicit regression fixture. Verify absence of removed visual AND collision content. A fresh APK proves packaging; install, execution, device readability and sustained performance require device evidence.
